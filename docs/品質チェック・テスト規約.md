# AI-Review-Agent 品質チェック・テスト規約

Vitest + TypeScript + Biome + dependency-cruiser によるコード品質チェック規約。

---

## Quality Check 一覧

| チェック | ツール | 対象 | コマンド |
|---|---|---|---|
| Lint/Format | Biome | 全ソース | `pnpm lint:fix` |
| 型チェック | TypeScript | 全ソース | `pnpm typecheck` |
| Prisma 型生成 | Prisma CLI | DB スキーマ | `pnpm prisma generate` |
| Unit テスト | Vitest | Domain, Application | `pnpm test:unit` |
| Integration テスト | Vitest + DB | Infrastructure | `pnpm test:integration` |
| 依存方向チェック | dependency-cruiser | 全ソース | `pnpm depcruise` |

### verify コマンド実行フロー

`pnpm verify` は以下の順序で自動実行：

```
1. pnpm lint:fix           # フォーマット + lint
2. pnpm prisma generate   # DB スキーマから型生成
3. pnpm typecheck          # TypeScript 型チェック
4. pnpm test:unit          # Unit テスト（Domain + Application）
5. pnpm depcruise          # DDD 4層依存ルール検証
```

**コード変更後は必ず実行し、全てパスすることを確認する。**

```bash
pnpm verify
# すべてパス → マージ可能
```

## 型チェック（TypeScript）

### ルール

- `any` 型の使用は原則禁止
- 一時的な回避が必要な場合は `// @ts-expect-error {reason}` で明記

```typescript
// OK
type User = {
  id: string
  name: string
}

// NG
type User = {
  id: any
  data: any
}

// 一時的な回避の場合
// @ts-expect-error TODO: fix this when library updates type definitions
const value: string = someLibraryFunction()
```

### CI で必ず実行
型エラーがある PR はマージ不可。

```bash
pnpm typecheck
# エラー例：
# src/backend/domain/models/review-comment.model.ts:42:10 - error TS2345:
# Argument of type 'number' is not assignable to parameter of type 'string'.
```

## Unit テスト（Vitest）

### テスト対象

- Domain モデル、サービス
- Application UseCase
- ユーティリティ関数

### 実行
```bash
pnpm test:unit              # 全テスト実行
pnpm test:unit --watch      # ウォッチモード
pnpm test:unit --coverage   # カバレッジレポート
```

### カバレッジ目標

| 層 | 最小カバレッジ |
|---|---|
| Domain | 80% 以上 |
| Application | 70% 以上 |

### テスト記述ルール

- モック無し（純粋関数のテスト）
- 外部依存（Gateway）は Mock
- `Result<T, E>` パターンの Success/Error 両ケース検証

---

## Integration テスト（Vitest + DB）

### テスト対象

- Infrastructure（Repository、Adapter）
- UseCase と Infrastructure の連携
- DB 操作の正確性

### 実
行
```bash
INTEGRATION_TEST=true DATABASE_URL=... pnpm test:integration
```

### 前提条件

- `INTEGRATION_TEST=true` 環境変数が設定されていること
- `DATABASE_URL` でテスト用 DB に接続
- 未設定時は自動スキップ

### テスト記述ルール

- 実際の DB に接続
- DB 状態を検証（戻り値だけでなく）
- `afterEach` でテストデータをクリーンアップ
- トランザクション・ロールバック検証

## 依存方向チェック（dependency-cruiser）

### ルール

DDD 4層の依存方向を厳格に検証。

```
presentation → application → domain ← infrastructure
```

### 許可される依存

- `presentation` → `application`、`presentation/composition`、`presentation/loaders`、`presentation/actions`
- `application` → `domain`
- `infrastructure` → `domain/gateways`、`domain/repositories`
- 同層間は相互参照可

### 禁止される依存

- `domain` が他層に依存（❌ domain → application）
- `application` が `infrastructure` に直接依存（❌ application → infrastructure adapter）
- `presentation/loaders` が `infrastructure` に直接依存

### 実行

```bash
pnpm depcruise
# 違反例：
# src/backend/application/usecases/execute-pr-review.usecase.ts
# → src/backend/infrastructure/adapters/gemini-ai.adapter.ts
# ❌ "application" cannot depend on "infrastructure"
```

## Pre-Push チェックリスト

```bash
# 1. Code changes
git add .

# 2. Run verify
pnpm verify

# 3. Confirm all pass
# ✅ Lint/Format
# ✅ Prisma generate
# ✅ TypeScript
# ✅ Unit Test
# ✅ Dependency Cruiser

# 4. Run Integration Test (if modified infrastructure)
INTEGRATION_TEST=true DATABASE_URL=... pnpm test:integration

# 5. Push
git push
```

## CI/CD パイプライン

GitHub Actions で PR 時に自動実行：

```yaml
# .github/workflows/code-check.yml
name: Code Check
on: [pull_request]
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: pnpm/action-setup@v2
      - uses: actions/setup-node@v3
        with:
          node-version: 20
          cache: pnpm
      - run: pnpm install
      - run: pnpm verify
      - run: INTEGRATION_TEST=true DATABASE_URL=${{ secrets.TEST_DATABASE_URL }} pnpm test:integration
```

全パス → マージ可能
