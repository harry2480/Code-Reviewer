# AI-Review-Agent Web フロントエンド実装方針

## 1. 概要

AI-Review-Agent の Web フロントエンドは、GitHub App の詳細設定・ダッシュボード・レビュー履歴表示を担当します。
Server Components デフォルト、DDD バックエンド との連携、および高いアクセシビリティ・パフォーマンスを実現します。

## 2. 技術スタック

### コア技術

- **Framework**: Next.js 15 (App Router)
- **Language**: TypeScript
- **Styling**: Tailwind CSS + shadcn/ui
- **UI Components**: shadcn/ui (Radix UI + Tailwind)
- **Data Fetching**: Server Components (loader) + Server Actions
- **State Management**: 最小限のクライアント状態（zustand は不要を前提）
- **ORM**: Prisma（type-safe DB access）

### 開発ツール

- **Linter/Formatter**: Biome
- **Testing**: Vitest + React Testing Library
- **E2E Testing**: Playwright（将来実装予定）

## 4. 機能要件

### Phase 1: MVP（ダッシュボード・設定）

#### 4.1 ダッシュボード表示

- **要件**:
  - GitHub App のインストール状態確認
  - 直近のレビュー統計（本日のレビュー数、平均応答時間、セキュリティ脆弱性検出数等）
  - レスポンシブデザイン対応（スマホファースト）
- **表示項目**:
  - GitHub App 設定状況（✅ Connected / ❌ Not Connected）
  - レビュー実行数（本日、週間、月間）
  - ポリグロット・エキスパート対応言語一覧
  - 予算消費状況（例：0.3 USD / 0.5 USD）
  - 直近のレビューサマリー（タイムスタンプ、PR タイトル、ステータス）

#### 4.2 レビュー履歴一覧

- **要件**:
  - GitHub で実行された AI レビュー履歴を表示
  - 絞り込み（言語、ステータス、日付範囲）
  - ページネーション or 無限スクロール
- **表示項目**:
  - PR タイトル、GitHub リンク
  - 対象言語、レビュー実行時刻
  - レビューコメント数、提案コード数
  - 「4つの眼」スコア（Logic, Security, Efficiency, Readability）

#### 4.3 設定ページ

- **要件**:
  - GitHub App 設定の確認・更新
  - 言語別エキスパート・ルールのカスタマイズ（有効/無効切り替え）
  - 予算管理設定（日次上限額）
  - CI 同期設定（Success 時のみ実行、Failure 時スキップ）

### Phase 2: 機能拡張

- レビューコメント詳細表示（Analysis Chain、Suggested Changes）
- Cursor/Claude Code プロンプト生成・コピー機能
- 学習データの可視化・分析
- 利用料金の詳細ダッシュボード

## 5. 非機能要件

### パフォーマンス

- First Contentful Paint (FCP): < 1.0 秒
- Time to Interactive (TTI): < 2.5 秒
- Cumulative Layout Shift (CLS): < 0.1
- Core Web Vitals: 全て "Good" レベル
- 戦略：Server Components でサーバーサイドレンダリング、ダッシュボード統計は ISR（Incremental Static Regeneration）で10分ごと再生成

### アクセシビリティ

- WCAG 2.1 Level AA 準拠（必須）
- キーボードナビゲーション対応（Tab, Enter, Escape）
- スクリーンリーダー対応（aria-label、role 属性）
- 適切な ARIA 属性の使用（aria-live, aria-expanded など）
- shadcn/ui コンポーネントで自動対応

### SEO

- メタタグ設定（title, description, og:image）
- ランディングページの構造化データ
- ダッシュボードはプライベート（noindex）

## 6. 実装ガイドライン

### コーディング規約

1. **Server / Client Components**
   - デフォルト：Server Component
   - `'use client'` は必要な場合のみ（インタラクション、リアルタイム更新）
2. **コンポーネント設計**
   - 単一責任の原則
   - Props Interface の明確な定義
   - shadcn/ui コンポーネント優先、カスタムは最小限
3. **型定義**
   - 全てコンポーネント TypeScript
   - `any` 型禁止
   - バックエンド型と整合性を取る（同じ Prisma スキーマから生成）
4. **スタイリング**
   - Tailwind CSS ユーティリティファースト
   - ダークモード対応（`dark:` プレフィックス）
   - レスポンシブデザイン（Mobile First）

### データフロー

1. **初期データ**: Server Component (loader) で取得 → Props で子に渡す
2. **クライアント更新**: Server Actions で処理 → revalidatePath で再取得
3. **リアルタイム更新**: 必要に応じて useEffect + fetch（最小限）

## 7. 実装順序

1. **基盤構築** （1 週間）
   - 認証・ルーティング
   - 共通 UI コンポーネント (Button, Card, Dialog など)
   - レイアウト (Header, Sidebar)

2. **ダッシュボード機能** （1 週間）
   - GitHub App 接続状態確認
   - 統計サマリー表示
   - リアルタイム更新（ISR）

3. **レビュー履歴機能** （1 週間）
   - 一覧表示
   - 絞り込み・ページネーション
   - 詳細表示（Analysis Chain など）

4. **設定ページ** （1 週間）
   - 言語別ルールのカスタマイズ
   - 予算管理設定
   - CI 同期設定
