# 最終要件定義書: AI-Review-Agent (V11.0 - Polyglot & Workflow Optimized)

## 1. プロジェクト概要

GitHub Pull Request (PR) において、熟練エンジニアの視点を持つAIが自動レビューを行うGitHub App。Vercel Hobby環境での運用を前提に、多言語エキスパート・プロンプト、CI同期、自己修正、および AI エージェント連携機能を完備した「究極の個人用開発パートナー」を実現する。

## 2. コアロジックと知能 (Advanced Intelligence)

### 2.1 熟練エンジニアの「4つの眼」

- **ロジック**: 境界値、例外処理、実行時エラー、破壊的変更の検出。
- **セキュリティ**: シークレット露出（自動マスク）、脆弱なパターンの指摘。
- **効率性**: 計算量（O(n) 等）、冗長なリソース消費、キャッシュ戦略。
- **可読性**: 命名規則、SOLID原則、プロジェクト規約遵守。

### 2.2 ポリグロット・エキスパート・モジュール

PR 内の拡張子を自動判定し、以下の言語固有のルールを動的に注入する。

- **TypeScript**: 型定義の厳密性、非効率な `any` 使用の指摘。
- **Python**: PEP 8 準拠、非効率なリスト内包表記、非同期処理の不備。
- **Swift**: 強制アンラップの禁止、メモリ管理（ARC）の考慮。
- **PHP**: 型宣言の徹底、最新バージョン（8.x）の構文活用。
- **Go**: エラーハンドリングの徹底、`goroutine` のリーク防止。
- **Rust**: 所有権と借用の最適化、不要な `.clone()` の指摘。

### 2.3 自己修正と背景抽出

- **二段階検証 (Self-Refinement)**: 生成フェーズの後に検証フェーズを設け、ハルシネーション（実在しないAPI等）を排除。
- **背景抽出**: 直近のコミットメッセージと影響範囲（呼び出し元）の検索結果を推論に反映。

## 3. ツール連携と表示仕様 (Developer Workflow)

### 3.1 AI Agent 連携 (Cursor / Claude Code)

- **Instruction Block**: レビューコメントの末尾に、Cursor や Claude Code のチャットに貼り付けて一括修正を指示できるプロンプトを自動生成。
- **Suggested Changes**: GitHub 上で即時適用可能なコードスニペットの提供。

### 3.2 UI と通知の最適化

- **Analysis Chain**: `<details>` タグ内に詳細な推論プロセス（CoT）を格納。
- **通知集約 (Batching)**: 1 PR ごとの通知をサマリー1通に集約し、開発の集中を妨げない制御。
- **GitHub Checks API**: レビューの進行状況（待機・実行・完了）を PR 画面に表示。

## 4. 技術アーキテクチャ (Vercel & Cloud Infrastructure)

### 4.1 システム構成

- **Runtime**: Hono / Node.js (Vercel Serverless Functions)。
- **非同期キュー**: Upstash QStash による Webhook 処理の非同期化。
- **状態管理**: Upstash Redis による履歴・学習データ・コスト集計。
- **AIエンジン**: Gemini 3.0 / OpenRouter (Adapterパターン実装)。

### 4.2 API 保護と予算管理

- **レート制限**: GitHub API 残量を監視し、指数バックオフによるリクエスト制御。
- **ハードリミット**: 1日のトークン消費上限（例: 0.5 USD = 約 77 円）を超えた場合の自動停止。

## 5. 運用と構築 (Operations)

- **CIステータス同期**: CI（Lint/Test）が「Success」になったタイミングで自動起動。
- **Manifest Setup**: GitHub App Manifest による権限設定の自動化。
- **フィルタリング**: ラベル（`ai-review`）やコマンド（`/review`）による手動実行制御。
