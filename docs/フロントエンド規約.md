# AI-Review-Agent フロントエンド規約

Next.js 15 App Router + shadcn/ui + Tailwind CSS におけるフロントエンド規約。

---

## ディレクトリ構成

`apps/webapp/` 配下:

| ディレクトリ | 責務 |
|---|---|
| `app/` | ページ・ルーティング。Server Component デフォルト |
| `components/` | React コンポーネント。`'use client'` は必要な場合のみ |
| `components/ui/` | shadcn/ui コンポーネント（Radix UI + Tailwind） |
| `features/` | 機能別モジュール（components, loaders, actions, hooks） |
| `lib/` | ユーティリティ・API クライアント |
| `types/` | グローバル型定義 |

## Server Components / Client Components の使い分け

### デフォルトルール

- **デフォルトは Server Component**。`'use client'` は必要な場合のみ付与
- **ルール例外なし**：Server Component で実装できるなら、常にそちらを優先

### Client Component が必要なケース

1. ユーザーインタラクション（ボタンクリック、フォーム入力、ホバー）
2. リアルタイム更新（WebSocket、polling）
3. ブラウザ API 依存（`window`, `localStorage`, `navigator`）
4. `useState`, `useEffect`, `useContext` など React hooks 使用

### 初期データ取得

- **必ず Server Component** (`page.tsx` + loader) で取得
- Props として子コンポーネントに渡す
- クライアント側の fetch は原則なし

### 例

```typescript
// ✅ OK - Server Component でデータ取得
// apps/webapp/app/(authenticated)/dashboard/page.tsx
import { DashboardLoader } from '@/features/dashboard/loaders'
import { DashboardContent } from '@/features/dashboard/components'

export default async function DashboardPage() {
  const data = await DashboardLoader.getStats()
  return <DashboardContent stats={data} />
}

// ✅ OK - Client Component で UI インタラクション
// features/dashboard/components/filter-button.tsx
'use client'

import { useState } from 'react'
import { Button } from '@/components/ui/button'

export function FilterButton() {
  const [isOpen, setIsOpen] = useState(false)
  return (
    <Button onClick={() => setIsOpen(!isOpen)}>
      Filters
    </Button>
  )
}

// ❌ NG - Client Component でデータ取得
'use client'
import { useEffect, useState } from 'react'

export function Dashboard() {
  const [data, setData] = useState(null)
  useEffect(() => {
    fetch('/api/stats').then(r => r.json()).then(setData)
  }, [])
}
```

## データフローと状態管理

### データ取得フロー

1. **初期データ**: Server Component (loader) で取得 → Props で子に渡す
2. **クライアント側の動的データ**: 必要に応じて `useEffect` + fetch（最小限）
3. **キャッシング**: Next.js Request メモ化、ISR で再検証

### 状態管理

- **グローバル状態**: ほぼ不要（Server Component 推奨で解消）
- **ローカル状態**: `useState` で十分（Modal 開閉、フィルタ UI など）
- **複雑な状態**: zustand（最小限、慎重に導入）

### ミューテーション（CUD操作）

- **Server Actions** を使用（推奨）
- 関数シグネチャ例：

```typescript
// features/settings/actions/update-language-rule.action.ts
'use server'

import { updateLanguageRule } from '@/backend/application/usecases'

export async function updateLanguageRuleAction(
  language: string,
  enabled: boolean
) {
  try {
    await updateLanguageRule({ language, enabled })
    revalidatePath('/settings')
    return { success: true }
  } catch (error) {
    return { success: false, error: error.message }
  }
}
```

- Form 実装例：

```typescript
// features/settings/components/language-toggle.tsx
'use client'

import { updateLanguageRuleAction } from '../actions'
import { Button } from '@/components/ui/button'

export function LanguageToggle({ language, enabled }) {
  async function handleToggle() {
    const result = await updateLanguageRuleAction(language, !enabled)
    if (result.success) {
      // UI 更新は Server Action の revalidatePath で自動
    }
  }

  return <Button onClick={handleToggle}>Toggle {language}</Button>
}
```

##型定義

### バックエンド との整合性

- Prisma スキーマから自動生成される型を使用
- 重複定義禁止
- バックエンド loader から返される型をそのまま使う

```typescript
// ✅ OK - Prisma 型を再利用
import { ReviewHistory } from '@prisma/client'

interface ReviewHistoryProps {
  histories: ReviewHistory[]
}

// ❌ NG - 重複定義
interface ReviewHistory {
  id: string
  prId: string
  ...
}
```

### API レスポンス型

- バックエンド presentation layer が定義した型を import

```typescript
import { ExecutePrReviewResponse } from '@/backend/presentation/types'
```
