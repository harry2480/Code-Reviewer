# AI-Review-Agent インフラ規約

pnpm workspace + Vercel Serverless Functions + Upstash (QStash / Redis) + GitHub App によるインフラ環境の構成と規約。

Vercel Hobby 環境での個人開発運用を前提。高速化・スケーラビリティ・コスト効率を重視。

---

## Monorepo 構成

pnpm workspace で管理。`apps/` 配下に各アプリケーション、`src/` 配下にバックエンド共有ロジックを配置。

```text
.
├── apps/
│   └── webapp/                   # Next.js 15 App Router フロントエンド
├── src/
│   ├── backend/                  # DDD 4層バックエンド（Hono ルーター）
│   │   ├── domain/
│   │   ├── application/
│   │   ├── infrastructure/
│   │   └── presentation/
│   └── prompts/                  # AI エキスパート・プロンプト（言語別）
├── pnpm-workspace.yaml
├── biome.json                    # 共有 lint/format 設定
├── tsconfig.json                 # 共有 TypeScript 設定
├── prisma/
│   └── schema.prisma             # Prisma ORM スキーマ
├── requirements.md               # 最終要件定義書
├── AGENTS.md                     # AI エージェント運用ガイド
├── CLAUDE.md                     # Claude Code 向け利用ガイド
└── package.json                  # workspace scripts
```

## デプロイメント

| 環境 | トリガー | プラットフォーム | AI エンジン | 備考 |
|---|---|---|---|---|
| **Development** | ローカル実行 | localhost:3000 / Vercel dev | Stub（環境変数 `STUB_MODE=true`） | テスト・開発用。実API呼び出しなし |
| **Preview** | PR 作成 / 更新 | Vercel Preview（PR ごとに一意の URL） | Gemini 3.0（環境変数 `AI_ENGINE=gemini`） | 本番同等のテスト環境 |
| **Production** | main ブランチへの push | Vercel Production | Gemini 3.0 or OpenRouter（環境変数 `AI_ENGINE=gemini` or `openrouter`） | 本番環境。Hobby plan 予定 |

### Vercel 設定

- **Framework Preset**: None（Hono は自動検出）
- **Runtime**: Node.js 20.x
- **Build Command**: `pnpm run build`
- **Install Command**: `pnpm install`
- **Function Memory**: 1024 MB（Hobby デフォルト）
- **Function Timeout**: 60 秒（Webhook 処理完了に十分）

### Vercel 環境変数

**全環境共通**:
```env
GITHUB_APP_ID=<Your GitHub App ID>
GITHUB_APP_PRIVATE_KEY=<Your GitHub App Private Key>
GITHUB_WEBHOOK_SECRET=<Random Secret>
```

**Preview / Production**:
```env
AI_ENGINE=gemini  # or openrouter
GEMINI_API_KEY=<Your Gemini API Key>
# or
OPENROUTER_API_KEY=<Your OpenRouter API Key>

UPSTASH_REDIS_REST_URL=<Your Upstash Redis URL>
UPSTASH_REDIS_REST_TOKEN=<Your Upstash Redis Token>

UPSTASH_QSTASH_URL=<Your Upstash QStash URL>
UPSTASH_QSTASH_TOKEN=<Your Upstash QStash Token>

DATABASE_URL=<Your Prisma Database URL>  # 任意（履歴保存用）

DAILY_TOKEN_LIMIT_USD=0.5  # 日次トークン消費上限（USD）
```

**Development**:
```env
STUB_MODE=true
DATABASE_URL=file:./dev.db  # SQLite local（任意）
```

## GitHub App 統合

### Webhook ハンドリング

- **エンドポイント**: `https://<vercel-deployment>/api/github/webhook`
- **トリガーイベント**:
  - `pull_request` — 新規 PR 作成・更新時
  - `pull_request_review` — PR レビュー追加時（不要なら無視）
  - `check_run` — CI ステータス更新時（CIが Success なら自動起動）
- **ペイロード検証**: GITHUB_WEBHOOK_SECRET で HMAC 署名検証
- **非同期処理**: Upstash QStash にキュー。Vercel Function の 10 秒 timeout 回避

### Checks API 統合

PR 画面に「AI Review」チェックを表示。進捗状況を可視化。

```
⏳ AI Review: In Progress (詳細解析中...)
✅ AI Review: Completed (レビューコメント投稿済み)
❌ AI Review: Failed (エラーまたは予算上限超過)
```

## Upstash 環境

### QStash（非同期キュー）

- **用途**: GitHub Webhook 受信 → 非同期でレビュー実行（Vercel timeout 対策）
- **リトライ戦略**: 指数バックオフ。最大 3 回リトライ
- **タイムアウト**: 5 分以内に処理完了できない場合は自動停止・ログ記録

### Redis（状態管理）

- **履歴保存**: レビュー実行履歴・学習データ
- **予算管理**: 日次トークン消費ログ・残高管理
- **キャッシュ**: コミット背景情報・呼び出し元キャッシュ（TTL: 1 日）

## AI エンジン・切り替え

### Adapter パターン（環境変数ベース）

- **Gemini 3.0**: 標準選択。Vercel Hobby での推奨（安価・高速）
- **OpenRouter**: 代替選択。複数プロバイダ対応（本番フェイルオーバー想定）

Composition Root で環境変数 `AI_ENGINE` を読み取り、該当アダプタを注入。

```typescript
// src/backend/presentation/composition/pr-review.composition.ts
const aiGateway = process.env.AI_ENGINE === 'openrouter'
  ? new OpenRouterAiAdapter(...)
  : new GeminiAiAdapter(...);
```

### Stub 実装（開発・テスト）

環境変数 `STUB_MODE=true` で Stub AI adapter に切り替え。本社 API 呼び出しなし。

## CI/CD パイプライン

### GitHub Actions（自動テスト・デプロイ）

- **Lint / Type Check**: PR 作成時に自動実行
- **Unit Test**: PR 作成時に自動実行
- **Integration Test**: `INTEGRATION_TEST=true` + `DATABASE_URL` 設定時のみ実行
- **Vercel Deploy**: main push で自動デプロイ

### CIステータス同期

`check_run` Webhook で CI ステータス（Success/Failure）を監視。

**Success 時**:

1. AI レビュー実行を QStash にキュー
2. Checks API で「In Progress」表示

**Failure 時**:

1. AI レビュー実行をスキップ（失敗 CI のコード品質が保証されないため）
2. Checks API で「Skipped」表示

## ローカル開発環境

### セットアップ

```bash
# 1. リポジトリクローン
git clone <repository-url>
cd code-reviewer

# 2. 依存インストール
pnpm install

# 3. 環境変数設定（.env.local）
cp .env.local.example .env.local
# STUB_MODE=true / DATABASE_URL=file:./dev.db に設定

# 4. DB 初期化（任意）
pnpm db:migrate

# 5. 開発サーバー起動
pnpm dev
```

### GitHub App ローカルテスト

- **Webhook トンネル**: ngrok / Vercel Local で localhost:3000 を外部公開
- **GitHub App 設定**: Webhook URL を `http://localhost:3000/api/github/webhook` に設定
- **テスト**: ローカルで PR 作成 → Stub AI がレビューコメント投稿

## Vercel Hobby 制限への対応

| 制限項目 | 値 | 対応 |
|---|---|---|
| Serverless Function Timeout | 10 秒 | Upstash QStash で非同期化 |
| Memory per Function | 1024 MB | 十分。大型モデル推論は避ける |
| 同時実行数 | 制限なし（従量課金） | Cold start 最小化（オンデマンド） |
| 出力サイズ | 6 MB | レビュー JSON は 100 KB 以下 |
