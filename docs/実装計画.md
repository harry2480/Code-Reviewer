# AI-Review-Agent 実装計画書

requirements.md の要件に基づき、GitHub PR 自動レビュー機能の実装手順を定めます。

---

## 実装フェーズ全体（約 8 週間想定）

| Phase | タイムライン | 主要マイルストーン |
|---|---|---|
| Phase 1 | 週 1-2 | バックエンド基盤、DDD 4層スケルトン |
| Phase 2 | 週 2-3 | 「4つの眼」コアロジック実装 |
| Phase 3 | 週 3-4 | ポリグロット・エキスパート（複数言語対応） |
| Phase 4 | 週 4-5 | 自己修正（二段階検証）、背景抽出 |
| Phase 5 | 週 5-6 | フロントエンド（ダッシュボード・設定） |
| Phase 6 | 週 6-7 | GitHub App 統合、Checks API 連携 |
| Phase 7 | 週 7-8 | テスト、本番化、最適化 |

## Phase 2: 「4つの眼」コアロジック（週 2-3）

### 2.1 ReviewEngine Service 実装
- [ ] Logic 評価ロジック（境界値、例外処理、破壊的変更検出）
- [ ] Security 評価ロジック（シークレット露出、脆弱パターン検出）
- [ ] Efficiency 評価ロジック（計算量、キャッシュ戦略）
- [ ] Readability 評価ロジック（命名規則、SOLID 原則）

### 2.2 Unit テスト（各視点ごと）
- [ ] Logic テスト：複数パターン（null check、off-by-one など）
- [ ] Security テスト：SQL injection、XSS など脆弱パターン
- [ ] Efficiency テスト：O(n)、O(n²)の検出
- [ ] Readability テスト：命名規則違反検出

### 2.3 初期プロンプト設計
- [ ] コアシステムプロンプト作成
- [ ] Few-shot examples 作成
